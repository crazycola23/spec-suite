# 决策登记总表

> 未定案的决策不阻塞无关的可逆工作。临时基线只有在负责人明确授权、且没有不可撤销后果时才可实现；迁移代价写在裁决单里。
> **不要等所有决策都关闭才做无关工作。** 字典层只冻结 authoritative source 已支持的事实；依赖决策的值保持 unresolved。

---

## 1. 总表

| ID | 要定什么 | 卡住的交付物 | 当前基线（不是结论） | 状态 | 参会 |
|---|---|---|---|---|---|
| <D-01> | <一句话> | <交付物 ID / 相对路径> | <方案 A：一句话> | <未定案 / 有会议方向 / 已定案> | <产品 + 技术> |

状态只有三种：

- **未定案** —— 还没讨论
- **有会议方向** —— 讨论过，方向有了，细节没定。**这不是已定案**，见 §3
- **已定案** —— 结论已回填真相源，拿到正式规则 ID，记入关闭日志

---

## 2. 议程排序

按"解锁多少交付物 ÷ 预计讨论成本"排，不按 ID 顺序排。

| ID | 解锁 | 讨论成本 | 优先级 |
|---|---|---|---|
| <D-05> | <数据模型根，下游 3 张表 + 全部事实归属> | <低：只有两个候选> | 1 |
| <D-04> | <费用全链路> | <高：要外部报价> | 3 |

**Heuristic：**优先关闭卡住数据模型根或下一道不可逆边界的决策；其余是否可延后由依赖图决定。

---

## 3. 「会议方向」是中间态，不是关闭

会开了、方向有了、细节没定，是最容易被记成"已关闭"的状态。固定写法：

```markdown
### 会议方向（<日期>）—— 不是已定案

方向：<一句话>

待补：
- <项 1>
- <项 2>

在以上各项冻结前，代码<不实现某行为，只做某保护性行为>。
```

**有"待补:"就还没关闭。** 这个写法让项目能记录进展而不谎报关闭。

---

## 4. 关闭一条决策的条件（全部满足才算）

```
1  结论明确到可以写成规则，不是"倾向于 A"
2  已回填真相源，拿到正式规则 ID
3  contracts/ 已按结论改完并重新生成
4  受影响的验收条件已补
5  受影响的追溯记录已补
6  被它阻塞的交付物已解除阻塞标记
7  记入关闭日志（日期 + 规则 ID + 谁拍的）
```

第 4、5 条最常漏，和缺口关闭的第 6、7 步是同一个失效模式：规则有了、代码写了、没有任何验收覆盖它。
